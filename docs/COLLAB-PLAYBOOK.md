# 双 AI 协作开发方法论（本项目实战沉淀）

> 本文记录 local-vault v0.1 的完整协作过程，可复用到任何"一人 + 多个 AI"的项目。

## 一、结论先行：什么有效

**Git 仓库 + 任务板 + 契约冻结 + 文件级归属**，四人（1 人 + 2 AI）并行开发零冲突。

| 机制 | 作用 | 本项目效果 |
|---|---|---|
| **文件级单一归属** | 两个 AI 物理上不碰同一文件 | src/ 归我，docs/ 归 Claude，全程零冲突 |
| **契约冻结** `docs/CONTRACTS.md` | 接口先定死，改前必须声明 | 评审意见全部落在契约层，改代码前就暴露问题 |
| **任务板** `TASKS.md` | 唯一调度中枢，含汇报区 | 你只传任务，不需理解技术细节 |
| **角色规范** `AGENTS.md` / `CLAUDE.md` | 铁律 + 各自边界 | AI 自己知道能改什么、不能碰什么 |
| **分级评审** `[CRITICAL]/[MAJOR]/[MINOR]` | 问题有优先级 | P0 真 bug 被主动揪出来 |

## 二、实战时间线（可复用的节奏）

```
1. Owner 定方向 + 角色分工
        ↓
2. 建骨架：AGENTS.md / CLAUDE.md / TASKS.md / docs/CONTRACTS.md
        ↓
3. 分工启动：
   - 执行手(AI-1)：按契约写代码
   - 架构师(AI-2)：写设计文档 + 预审契约   ← 可完全并行
        ↓
4. AI-2 契约层预审 → 提 [CRITICAL]/[MAJOR]/[MINOR]
        ↓
5. AI-1 逐条裁决（采纳/回怼）→ 先改契约 → 再写代码
        ↓
6. AI-1 提交代码 + 测试 + 运行证据
        ↓
7. AI-2 代码级复审（逐行号 + 隐私扫描）→ 提 P0/P1/P2
        ↓
8. AI-1 修 P0（顺带修 P1/P2）→ 补回归测试
        ↓
9. AI-2 复核 → 通过 → Owner 合入 + 打 tag
```

## 三、关键经验（踩过的坑）

1. **契约比代码先冻结**。我们的 7 项评审意见全部产生在契约层，等于**在写代码前就消灭了一批 bug**。这是最高杠杆的一步。

2. **测试要卡死回归**。Claude 抓到的 `meta 错位`（model_name 存成 embed_backend）是隐蔽 bug——换模型不重建、旧新向量混用。修完我加了 `test_model_name_change_triggers_reindex`，让这类 bug 再也回不来。

3. **执行手要敢裁决，不要盲从**。Claude 的 7 项 MAJOR 我 6 项采纳、1 项记为已知局限但加了兜底。评审意见要**过脑子**，不是照单全收。

4. **边界是双向的**。我发现 `DESIGN.md` 里 exts 数量过时了，但**我没去改**——因为那是 Claude 的文件。改他的文件就破了给他立的规矩。只在 TASKS.md 留言。**规矩对所有人一视同仁才有约束力。**

5. **每个 AI 都必须给出"运行证据"**。铁律第 5 条"可跑才算完"逼着我们贴 pytest 输出、端到端日志。没有证据的"完成"是耍流氓。

6. **隐私/安全红线单独设卡**。本项目第一优先级是"零上传"，所以让 Claude 的头号任务是**审我有没有偷偷联网**。结果他揪出了 `create_connection` 绕过 `socket.connect` 的后门——**专门的审查者能发现执行者的盲区**。

## 四、模板文件清单（开新项目照抄）

```
新项目/
├── AGENTS.md          # 全局铁律：角色、流程、命名、自检清单
├── CLAUDE.md          # 给 AI-2 的边界与任务
├── TASKS.md           # 任务板 + 契约修订区 + 汇报区
├── docs/
│   ├── CONTRACTS.md   # 接口契约（冻结）
│   └── REVIEW.md      # 评审记录（分级）
└── docs/HANDOFF-*.md  # 交接给另一个 AI 的开工指令
```

## 五、给 Owner 的操作要点

- **你不需要懂技术**。你是调度员：把 A 的产物质疑转给 B，把 B 的需求转给 A。
- **一次只让一个 AI 改一个文件**。冲突的唯一来源是文件重叠，物理隔离掉就没事。
- **AI 之间没有直接通道**，靠你和仓库传话。这是当前最实际的做法（MCP 互调能做但配置成本高，不值得为第一个项目上）。
- **保留 git 历史**。每次提交都是可回滚的检查点，AI 犯错也不怕。
